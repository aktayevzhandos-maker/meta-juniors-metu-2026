# Ручная проверка — Жандосу

Backend проверяется отдельно от будущего интерфейса Алмаса. Сначала выполните запуск из README. В браузере `/api/v1/health/` должен вернуть 120 профилей, `database: postgresql` и `offline: true`. Поиск — POST, ввод адреса поиска в браузерной строке даст 405 и не означает поломку.

Пример в PowerShell:

```powershell
$body = @{query='Нужен специалист по GMP и клиническим исследованиям из Алматы'; limit=3} | ConvertTo-Json
$result = Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/v1/search/' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$result.results | ConvertTo-Json -Depth 10
```

После подключения frontend:

1. Ввести запрос выше. В топ-3 должен быть EXP-001, в объяснении GMP и клинические исследования, город Алматы. Имена явно синтетические.
2. Перефразировать: «В Алматы нужен эксперт: надлежащая производственная практика, клинические испытания». Проверить сохранение релевантности.
3. Ввести свой новый запрос по компетенциям реестра. Проверить карточки через `GET /experts/{id}/`: каждый указанный совпавший навык действительно есть в skills, отрасль совпадает с профилем.
4. Запросить «GMP и SCADA». Ожидать partial, явные недостающие условия. Система не должна обещать полного соответствия.
5. Запросить «Квантовая телепортация в Алматы». Ожидать no_matches; совпадение только города не должно давать ложного эксперта.
6. «Нужен SCADA без PLC»: показанные профили не содержат PLC. Не считать обработку всех возможных отрицаний реализованной.
7. «Python NLP от 30 лет»: частичные результаты, недостающее условие по опыту.
8. Найти занятых экспертов в CSV. При равной релевантности доступный должен быть выше занятого; занятый с полным набором требований может быть выше свободного с неподходящими навыками.
9. Проверить отраслевой фильтр поверх текста. Пустой запрос и только dropdown не заменяют сценарий поиска.
10. Отключить интернет, повторить поиск и перезагрузку UI. Никакие шрифты, данные, LLM или скрипты не должны загружаться из сети. Убедиться, что на frontend видна пометка о синтетических данных.

Для воспроизводимой оценки запустить обе команды `evaluate_search` из README. Записать Hit@3, число запросов, median/p95/max и дату. Нельзя сообщать метрики, пока команда не завершилась успешно. Семь эталонов и набор перефразировок составлены командой; это не независимые данные жюри. Дополнительно попросить человека, не писавшего алгоритм, составить 5 новых запросов и заранее отметить релевантные ID до запуска поиска.

Для бага: исходный запрос, выбранный фильтр, ожидаемые ID, фактические ID, текст предупреждений и время ответа. Не собирать реальные персональные данные. Слайды пока не создавать: сначала проверить метрики и живое демо.

# Проверка поиска — 20.11.2026

**Исторический исходный прогон: приёмка не пройдена.** Hit@3 достиг 85%, но найдены ошибки разбора ограничений. Код поиска и исходный реестр во время того прогона не менялись. Затем ошибки исправлены; актуальные результаты: [проверка исправлений](CONSTRAINT_FIX_RESULTS.md).

## Метод и воспроизводимость

- [Замороженные запросы и ожидаемые ID](acceptance_cases.json): 20 положительных и 5 отрицательных сценариев. Все релевантные ID рассчитаны по явно заданным правилам CSV до первого HTTP-запроса, без импорта поискового движка.
- [Исходные ответы API и замеры](acceptance_before_constraints_fix.json). В файле есть SHA256 данных и набора, Git HEAD. Во время теста существовали незакоммиченные изменения frontend.
- Набор новый, но **не независимый слепой benchmark**: автор видел реализацию. Разметка и оценка не проводились ментором или пользователями AIID. Для независимой оценки нужен отдельный человек и новые формулировки.
- Запросы шли через настоящий localhost HTTP в Docker/Django/PostgreSQL; проверен также proxy frontend. Интернет физически не отключался, Qwen не использовалась.
- После прогона сверены все 120 записей API с CSV. SHA256 локального и контейнерного `search/engine.py` совпали: `30dfbe6557feee2f1477e0b58d8c1073175a0cc815c22201287667e4b425c94d`.

Повторить из корня: `python scripts/test_search_acceptance.py` через подготовленную `.venv`, при запущенном Compose. Команда сохраняет новый отчёт и возвращает ненулевой код при провале приёмки. Ожидаемые ID определяются независимо от выдачи; не менять их, чтобы скрыть ошибки. После исправлений этот набор становится регрессионным, а финальная оценка требует нового набора.

## Воспроизводимые ошибки

| Приоритет | Запрос | Наблюдение | Требуемое поведение |
|---|---|---|---|
| P0 | `GMP, но не из Алматы` | Два эксперта из Алматы помечены full; город прочитан как положительное требование. При этом один релевантный кандидат попал в топ-3, поэтому обычный Hit@3 скрывает ошибку | Распознать исключение города; не помечать запрещённый город как полный матч |
| P0 | `GMP, опыт не более 10 лет` | Условие превращено в минимум 11 лет; все три кандидата нарушают верхнюю границу | Отдельно распознавать верхнюю границу опыта, не терять отрицание |
| P1 | `Без PLC нужен специалист по SCADA` | Пустая выдача, хотя подходящие ID существуют | Ограничить область отрицания PLC; SCADA остаётся положительным требованием |
| P1 | `Фармацевтика от 5 лет без Python` | Пустая выдача при существующих подходящих профилях | Исключение не должно блокировать поиск по отрасли; служебные слова не должны становиться обязательным лексическим сигналом |
| P1 | `GMP в Ташкенте` | Три кандидата с full, хотя этого города в базе нет. Ташкент вынесен в неизвестные слова, общее предупреждение присутствует | Явно сообщить, что географическое условие не выполнено/не поддержано; избегать впечатления полного покрытия исходного текста |

## Что делать следующим

Сначала исправить отрицания географии и верхнюю границу стажа, затем область действия «без» и неизвестные географические условия. Проверить обратную совместимость API с frontend; Qwen для этих исправлений не обязательна. На текущем этапе исправления не внесены.

Не заявлять перед жюри «качество подтверждено независимо» или «любой запрос понимается». Перед защитой остаются новый набор от Жандоса/ментора, проверка полноценного UI при отключённом внешнем интернете и контрольный прогон после исправлений.

# AIID: Discovery Matrix

20.11.2026. Анализ существующего MVP; интервью с AIID не проводились. Рабочая продуктовая гипотеза: координатору нужен проверяемый короткий список людей под задачу, а не ещё один каталог.

**Обозначения:** Ф — факт из источника; Р — реализовано в коде; Г — гипотеза, требующая проверки. P0 — критично для защиты, P1 — следующий приоритет, P2 — после обязательного сценария. Результаты предыдущих прогонов не перепроверялись в рамках Discovery; база, код и инфраструктура не изменялись.

## Сравнение существующих способов

Это аналитическое сравнение классов решений, а не наблюдение за внутренними инструментами AIID. Кроме поиска через контакты, использование перечисленных альтернатив Альянсом не установлено.

| Способ | Сильная сторона | Ограничение | Вывод для MVP |
|---|---|---|---|
| Личные контакты | Контекст и доверие знакомому человеку | По ТЗ — дни на поиск; охват и маршруты передачи неизвестны | Сохранить человеческую проверку, сократить первичный поиск |
| Excel/CSV | Простой обмен и просмотр структуры | Сверка условий и порядок кандидатов обычно остаются человеку | Использовать как источник, не выдавать импорт за весь продукт |
| Ключевые слова | Прозрачный поиск точных терминов | Без нормализации чувствителен к формулировкам | BM25 + стемминг + проверяемые синонимы — текущая основа |
| Каталог с фильтрами | Точные ограничения по известным полям | Пользователь сам выбирает категории; одного такого сценария недостаточно по ТЗ | Отраслевой фильтр дополняет текст, а не заменяет его |
| Семантический поиск | Может находить близкие формулировки | Это ожидаемая способность подхода, не измеренный результат нашего MVP; нужны локальные веса и оценка ошибок | Не внедрять ради слова AI; сравнивать с baseline на закрытом наборе |

## Небольшой внешний research

| Проверенный пример | Что подтверждено первичным источником | Наш вывод, не утверждение источника |
|---|---|---|
| [NIH RePORT Matchmaker][S6] | Научный текст используется для поиска похожих проектов или связанных с ними program officials | Текст задачи может быть входом в поиск экспертизы; это не доказательство качества для промышленного AIID |
| [ORCID API][S7] | Документирован поиск по ключевым словам и организациям; ORCID отдельно предупреждает о сопоставлении людей только по имени | Для будущего реального реестра нужны устойчивые ID и источники фактов; не предлагаем сбор персональных данных на хакатоне |
| [VIVO][S8] | Связывает сведения об исследованиях через общий словарь и семантические технологии | Ценность реестра зависит от качества связей и описания компетенций; поиск экспертов не является новым изобретением |

Ни один источник не подтверждает, что AIID использует эти продукты или нуждается в их полном аналоге. Новые интеграции не предлагаются в scope хакатона.

## Что уточнить у ментора в первую очередь

1. Кто вводит запрос и кто принимает окончательное решение? Попросить один недавний пример без персональных данных.
2. Что означают «GMP», «аудит» и «опыт» в критериях пригодности: достаточно заявленного навыка или нужны проекты/сертификаты?
3. Какие условия жёсткие: город, очное участие, минимальный стаж, занятость? Можно ли показывать частичное совпадение?
4. Кто подтверждает доступность и актуальность профиля? Как часто сведения меняются?
5. Что считать успешным пилотом: короткий список, согласованный контакт или состоявшаяся консультация? Ответов пока нет.
